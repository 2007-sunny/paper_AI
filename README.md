# PaperAI

以 PDF 為中心的英文論文與教科書閱讀器。打開就回到上次讀到的地方，滑鼠移到看不懂的段落，按一下 Ctrl，譯文就直接蓋在原文上；再按一次就消失。

## 功能

### 閱讀

- **PDF 閱讀**：左側欄像 VS Code 一樣開啟檔案或資料夾，資料夾以樹狀顯示，可逐層展開。右側直接顯示原始 PDF，不會複製檔案，只記錄路徑。重新開啟時回到上次的檔案、頁碼與縮放。
- **縮放**：觸控板雙指縮放會像看圖片一樣連續放大，停下後才重畫成清晰的頁面；Ctrl+滾輪或右上角的 −／＋ 也可以縮放。上千頁的書縮放也不會卡，重畫時舊畫面先留著，不會閃白。
- **書籤與目錄**：按工具列的「書籤」，側邊欄列出自己加的書籤和 PDF 內建的目錄。目錄可以自己編輯（改名、調層級、排序、插入），掃描書沒有目錄時可以從空白開始建；編輯過的目錄可以還原。
- **標記與註解**：選字後在浮動選單點顏色就標記，按「註解」加上說明。沒有文字的地方（掃描頁、圖、公式）用工具列的「▭ 框選」拖曳畫方框再寫註解。左下角齒輪的「註解列表」依頁碼列出所有標記，點了跳回原位。
- **歷史與刪除**：看過的文件都留在左下角齒輪的「歷史管理」。刪除分三步：確認首頁與標題、閱讀永久刪除說明、按下確認。只會刪除翻譯資料，不會刪除原始 PDF。

### 翻譯

- **Ctrl 段落翻譯**：單獨按下並放開 Ctrl，切換滑鼠所在段落的譯文。Ctrl+C、Ctrl+滾輪不會觸發。譯文會用放得進框的最大字級，跟著頁面一起縮放。
- **兩層翻譯**：
  - 粗翻：按 Ctrl 時才呼叫 Google Cloud Translation，約 0.7 秒；翻過的段落存在本機，不會重複計費。
  - 細翻：讀到某一頁時，MinerU 只解析這附近 3 頁，本機模型再細翻這一頁和下一頁，完成後自動換掉粗翻，公式以 MathJax 顯示。PDF 段落和解析結果切法不同時（段落中間夾公式、參考文獻合成一塊），也會把相鄰的幾塊細翻接起來。
- **單字查詢**：在 PDF 或譯文上選字，按「查詢」先看到 Google 譯名，本機模型再依上下文補充。
- **每月上限**：粗翻預設每月最多送出 45 萬字元，可在「設置」調整，最高 50 萬；用量顯示在左下角。達到上限後不再呼叫 Google，等待本機細翻。

### 擷取給 AI

- **擷取內容**：選取文字後按「擷取內容」，取得所在整段的內文與 LaTeX 公式（包含夾在中間的獨立公式），複製後貼到任何 AI，不必截圖。對話框裡按「只擷取選取的部分」可以只取選取的範圍。安裝 `anthropic` 套件並設定環境變數 `ANTHROPIC_API_KEY` 後，也可以在閱讀器內直接問 Claude（選用）。
- **擷取圖片**：游標移到圖上會自動框出整張圖，按「擷取圖片」就以高解析度複製到剪貼簿，按鈕平時淡化。點陣圖與向量圖都支援；整頁掃描的書無法自動認圖。

### 掃描檔

- **沒有文字層的掃描頁**：自動用本機 OCR 辨識，才能按 Ctrl 翻譯、選字、查詢與擷取。
- **舊期刊掃描檔**（例如 1980 年代的 PRL）：內建的文字層常是破碎的舊 OCR（缺字、公式亂碼），粗翻與細翻都會出錯。到「設置」→「文字來源」按兩次「重新製作 OCR 並覆蓋原始 PDF」，PaperAI 會重新辨識掃描頁，把新的隱形文字逐字對齊寫進原始 PDF。畫面不會改變，電子版頁面不動；第一次覆蓋前，原檔會備份到 `output/<文件名稱>/original/`。這是 PaperAI 唯一會改動原始 PDF 的功能。

## 設置

滑鼠移到左下角齒輪，選「設置」，改了立即生效。

- **細翻模式**，可套用到所有文件或只套用到目前文件：
  - 自動：讀到哪裡，就解析並細翻到哪裡。
  - 按 Ctrl 才翻：先顯示粗翻，同時只細翻這一段。
  - 關閉：省電，不用 GPU，停止解析、細翻和單字的本機補充。已完成的細翻照常顯示；還沒解析的頁面擷取內容時只有 PDF 文字。
- **文字來源**：重新製作目前文件的 OCR（見上方「掃描檔」）。
- **進階**：
  - 縮放：觸控板與 Ctrl+滾輪的靈敏度、停下多久後重畫清晰頁面。
  - 譯文字級：最大字級（頁高的千分比，跟著縮放）與最小字級。
  - 翻譯與解析：預先細翻頁數、本機模型、粗翻每月上限、解析模型閒置後釋放 VRAM 的時間、每段解析逾時。
  - 還原預設值。

## 需求

- Windows（目前只在 Windows 11 測試過），Python 3.10 以上
- [Ollama](https://ollama.com/download)，以及一個翻譯用模型
- 建議有 NVIDIA 顯示卡。開發環境是 RTX 4060 Laptop（8GB）
- 解析 PDF 使用 [MinerU](https://github.com/opendatalab/MinerU)，裝在獨立環境，模型約 2GB；沒有安裝時改用 [Marker](https://github.com/datalab-to/marker)。只在本機解析，不會把文件傳到 MinerU 的雲端服務
- Google Cloud Translation API 金鑰（粗翻與單字查詢使用）
- 公式（MathJax）與 PDF 顯示（PDF.js）由 CDN 載入，需要網路

## 安裝

```powershell
git clone https://github.com/2007-sunny/paper_AI.git
cd paper_AI
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-pdf.txt
python -m spacy download en_core_web_sm
ollama pull gemma4
python -m venv .venv-mineru
.venv-mineru\Scripts\python -m pip install -r requirements-mineru.txt
.venv-mineru\Scripts\mineru-kit models download --tier standard
```

在專案根目錄建立 `.env`（不會提交 Git）：

```
GOOGLE_TRANSLATE_API_KEY=你的金鑰
```

金鑰到 Google Cloud Console 啟用 **Cloud Translation API** 後建立，並把 API 限制設成只允許這個 API。本機模型可在閱讀器的「設置 → 進階」切換，清單來自 `ollama list`。

## 使用

雙擊 **`PaperAI.bat`**，或在終端機執行 `python server.py`，瀏覽器會開啟 <http://127.0.0.1:8000/>。更新程式後要重新啟動服務才會生效。

1. 按「開啟檔案」（可多選）或「開啟資料夾」。打開後立即可讀，讀到哪裡才解析到哪裡。按 × 關閉只會移到歷史，不會刪除資料。
2. 滑鼠移到段落上，按一下 Ctrl 看譯文，再按一次隱藏。淡黃框是粗翻，綠框是細翻；在譯文上按 Shift+Ctrl 可以在粗翻與細翻之間切換。細翻沒翻成中文時會自動改顯示粗翻，並重新細翻一次。
3. 選取文字後，用浮動選單查詢單字、擷取內容或標記。那幾頁還在解析時，擷取內容先顯示 PDF 文字，完成後自動換成 LaTeX。
4. 游標移到圖上，按「擷取圖片」複製，再貼到 AI。
5. 按工具列的「書籤」加書籤、看目錄；按「▭ 框選」在沒有文字的地方畫框註解，Esc 結束。
6. 掃描檔選字或翻譯很亂時，到「設置 → 文字來源」重新製作 OCR。
7. 引用跳轉：`http://127.0.0.1:8000/?doc=<文件名稱>&page=<頁碼>&bbox=x0,y0,x1,y1` 會開到該頁並畫框（bbox 單位 point，可省略），按 × 或 Esc 清除；不會改掉原本記住的閱讀位置。改用 `?pdf=<完整路徑>` 時，已開啟資料夾內、還沒加入書庫的 PDF 會先詢問是否加入。
8. 要刪除翻譯資料時，把滑鼠移到左下角齒輪，選「歷史管理」，再按文件旁的「刪除」。

**外傳的資料**：按 Ctrl 翻譯的段落與查詢的單字會傳送到 Google；使用 API 問 Claude 時，該段內容會傳送到 Anthropic。細翻與 OCR 只在本機執行。

**只存在本機書庫、不寫回 PDF 的資料**：標記、註解、書籤、編輯過的目錄。

## 運作方式

```
PDF ─PyMuPDF─▶ 每頁文字與座標 ─按 Ctrl─▶ Google 粗翻 ─▶ 覆蓋在原段落
 │        （掃描頁：本機 OCR＋版面分析）
 │
 └─讀到該頁─▶ MinerU 解析附近 3 頁 ─▶ 切區塊與術語 ─▶ 本機細翻 ─▶ 依單字重疊換掉粗翻
```

只處理正在閱讀的文件。自動模式下，目前頁缺解析就先解析，再細翻，讀到一段的最後一頁時才處理下一段。解析結果存在 `output/<文件名稱>/chunks/`，重新開啟不必再轉。解析前會先把頁面轉成純圖片，避開損壞的文字層，暫存檔在解析服務停止時刪除。解析模型常駐，閒置 5 分鐘後釋放 VRAM；解析時會先卸載本機翻譯模型，之後再自動載入。粗翻與 OCR 不佔 GPU。分段轉檔之前產生的文件沿用原本的完整 Markdown。

本機細翻以英文句子為單位，用 JSON schema 要求回傳等長譯文，結果依（提示詞版本、模型、句子、本段術語）快取。術語在 `glossary.json`，其中的 `aliases` 也會套用到粗翻，把常見的中國用語改成台灣用語。

## 測試模型速度與品質

```powershell
python tools/bench_models.py --input "xxx.md" --models gemma4:latest qwen3.5:9b --paragraphs 5
```

`--input` 需要完整的 Markdown，也就是分段轉檔之前產生的文件；分段文件沒有這個檔案。GPU 比例低於 100% 代表模型有一部分在 CPU 上執行，速度會明顯下降。逐句對照報告存在 `output/<文件名稱>/bench/`，實測紀錄見 [進度.md](進度.md)。

## 已知限制

- 粗翻的公式來自 PDF 文字層，下標與上標會失真；正確公式要等細翻。
- OCR（RapidOCR，CPU）每頁約 1–4 秒，捲動停下後才辨識目前頁與前後各一頁，結果存在 `output/<文件名稱>/ocr/`。OCR 會認錯字，數學符號與上下標只能認成平面文字（例如 I_c 認成「I。」）；正確公式要等細翻。
- 重新製作 OCR 一次最多 300 個掃描頁；寫入希臘字母需要 Windows 內建的 Arial 字型。之前已辨識過的掃描頁，透明文字層仍是整行放置，重新製作 OCR 後才會逐字對齊。
- 一段解析超過 4 分鐘會放棄，維持粗翻，重啟服務後再試。實測 MinerU 每段約 25 秒，第一次載入約 1 分鐘。
- 跳到別頁時要等目前這段處理完或逾時，粗翻不受影響。切到「關閉」會直接結束解析，那一段之後要重做。
- 「已全部細翻」只代表解析出的段落都翻完；PDF 的某些段落仍可能對不到細翻而顯示粗翻（例如被 OCR 從中間切成兩塊時，兩塊會顯示同一段細翻）。
- 擷取內容的獨立公式是 LaTeX；行內公式取決於 PDF，部分文件只會得到近似文字。只擷取選取的部分時，頭尾若是公式，偶爾會多帶一個字。圖說不會隨圖片一起複製，要另外擷取。
- 有框線的表格也會被認成圖，少數版面的圖片裁切會帶到一點圖說。
- 解析模型與本機翻譯模型同時載入時 VRAM 接近 8GB 上限，所以翻譯模型會在解析前後反覆載入，每次約 15 秒。
- 分段解析看不到整份文件，頁首頁尾與標題層級的辨識可能比整份轉檔差。
- 譯文放不下時字級會縮小，到最小字級（預設 10px，可在設置調整）後改為框內捲動。
- 解析模型與本機翻譯模型第一次載入約需 1 分鐘，這段時間只有粗翻與 Google 查詢結果。
- 目前沒有自動化測試。

## 專案結構

| 路徑 | 用途 |
|---|---|
| `PaperAI.bat` | 雙擊啟動本機服務（Windows） |
| `server.py` | 本機服務入口 |
| `paperai/` | 翻譯流程、本機服務與網頁模板 |
| `glossary.json` | 術語表（所有文件共用） |
| `tools/bench_models.py` | 模型速度與翻譯品質比較 |
| `output/` | 轉換結果、翻譯快取、OCR 結果、原檔備份與資料庫（不提交） |
| `experiments/` | 早期的分析流程與原型，不參與正式流程 |
| `docs/maintenance.md` | 程式維護索引 |
| `進度.md` | 開發進度、模型實測與後續計畫 |

`AGENTS.md`、`CLAUDE.md` 與 `.claude/` 是給 AI 程式助理看的開發說明。
